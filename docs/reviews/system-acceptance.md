## 审核中发现并修复

- 全页面浏览器回归发现重复推荐在规则版本/评分改变时触发 MySQL generated-key 多行异常；先补复现测试确认 500，再改为唯一曝光键写入后查询稳定事件 ID，确保刷新、规则变化不重复曝光且不报错。
- 初次无历史预测出现 Java 条件表达式将 null 拆箱的错误，改为显式空值分支；独立测试确认 `count=null`。
- 实际 MySQL 并发测试暴露空范围 UPDATE 的间隙锁冲突，以及容量计算读快照滞后；改为按已存在主键清理超时、READ_COMMITTED 下持有菜品锁后读取占用。两个不同老人争用有限份数分别成功/拒绝，同老人餐次并发仅一个订单。
- 支付通知在订单锁后重新锁定支付记录，防止两个同时通知重复入账；退款失败保留原幂等号重试，成功补贴反向账本唯一。
- 模拟支付通知加入 HMAC-SHA256 验签，篡改金额、渠道、单号或签名均拒绝；生产 profile 无模拟接口。
- 浏览器实测发现数字表单默认步长阻止小数金额提交，补充 `step=any`。下拉测试通过真实控件外层点击，符合 Element Plus 的交互方式。
- 公告编辑补齐原接收角色/网点，避免编辑正文清空范围；上传材料审核改为只读；健康与权限选择以名称展示。
- 手机端日期切换的请求竞态先由前端两项测试复现：旧候选未清空、旧请求迟到覆盖新日期。增加候选加载锁、清空旧选择和请求代次校验，加载时禁止提交；避免把旧日期份数带到新日期。
- 多角色组合增加两项真实数据库回归：家属在非任职网点的已审核关联仍可查看补贴、推荐及本人订单，但不能借社区角色修改该网点老人状态或读取配送清单；此类家属订单不误记社区代办。
- 个人大字偏好持久化，角色导航与菜单拒绝保持一致；补齐订单日期/状态/网点筛选、支付流水、退款时原价/补贴/实付核对及每日过敏原编辑。
- 上传用途增加角色检查，附件下载检查具体绑定/申请/评价/工单与网点关系；审计失败摘要只记录错误代码和接口，不回显健康/密码原文。
- 前端按需注册组件并分离图表渲染模块，主 JS 从约 1,068KB 减为约 457KB，图表延迟加载；最终构建无超大分包警告。
