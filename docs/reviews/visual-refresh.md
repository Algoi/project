# 浅绿色视觉与图片完善

日期：2026-10-17。按用户偏好采用浅绿色主视觉和米白底色，保持绿色系的按钮、导航、图表和焦点样式。深色文字保证阅读，错误/警告保留少量语义色。颜色变量、图片路径和完整生成提示词见 [素材与视觉规范](../visual-assets.md)。

## 本轮实现

- 登录页加入社区助餐场景图，手机保留可直接使用的登录表单。
- 四角色首页加入场景图和按角色展示的常用服务入口，快捷入口遵循菜单禁用权限；账号、网点、公告继续读取真实接口。
- 订餐页优先展示已上传的私有图片；无图片、读取失败或解码失败时展示明确标注的本地示意图。
- 修复旧图片请求覆盖新餐品和组件销毁后创建临时 URL 的问题；切换和卸载时释放图片 URL。
- 全局采用浅绿、米白与深绿文字，图表读取同一组绿色变量，以实线/虚线辅助区分序列。

## 测试与审核

先补充 DishImage 的缺图、异步请求竞争、读取/解码失败和销毁后回包 4 项测试，原实现均失败后修复；另补首页快捷入口的角色与权限测试。全站浏览器回归发现菜谱接口返回空营养覆盖值时，页面会在后续预测请求结束前提前渲染并报错；先补回归测试确认失败，再改为初始化营养字段后发布菜谱数据，测试覆盖预测等待期间的显示和编辑，保留失败与修复后的记录。

- 类型检查、23 项前端测试通过；包括原登录权限、订餐请求竞争和模块边界检查。
- 生产构建通过，图片随本地前端构建发布，无外部图片网站依赖。
- 使用真实 Chrome 的桌面和 Pixel 7 页面完成 36 项回归覆盖，包括新增场景图、菜品示意图，以及原有全部业务流程。首轮 34 项通过，2 项桌面菜谱相关用例失败；修复后两项桌面复测均通过（53.0 秒和 11.5 秒），手机端相关用例也已通过。36 项用例最终均有通过记录，首轮失败记录保留。
- 全站业务回归后的 6 项金额、支付、订餐、核销、退款台账和交付完整性核对均为 0 个异常。
- 已检查桌面/手机登录页与首页，页面没有横向溢出。绿色按钮白字对比度约 6.13:1，浅绿区域深色文字约 8.35:1。

没有把示意图登记成菜品实拍附件，也没有覆盖用户上传的图片；图片仅影响展示，饮食安全、金额和库存仍由原后端规则处理。
