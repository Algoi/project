后续变更：本记录保留首批交付时的执行证据。用户随后要求演示账号无后缀、密码与账号同名，当前规则与网页复测见 [演示账号调整记录](demo-accounts.md)。

## 本批交付范围

- 根目录作为工程根，`server/`、`web/`、`scripts/`、开发文档 `docs/`；原设计包保留。
- Java 17 / Spring Boot 3.5.16 / MyBatis-Plus 3.5.17；Vue 3.5.22 / Vite 7.1.12 / Element Plus 2.14.7，其他业务依赖遵守第 11 章。

- Flyway V1 导入原 36 张业务表及初始角色/推荐权重，V2 增加认证会话表。
- 登录、退出、本人信息、本人密码、角色读取、网点授权读取、统一错误与分页、受认证保护的 OpenAPI 文件。
- 四角色首页、个人信息与改密页面、角色切换、当前网点选择、家属大字和移动布局。
- 两网点、四角色本地演示账号。演示密码从本地环境注入，初始化拒绝覆盖已有用户。

接口清单与字段见 [API 说明](../api/batch-01.md)。运行步骤见 [根 README](../../README.md)。本批不完成账号/网点管理 CRUD 或任何订餐业务，原 33 项需求均保留未验收状态。

## 先测试，再实现与修正

1. 先建立工程骨架、迁移及 22 项认证/权限集成用例，保留未实现认证版本的独立快照运行测试：22 项全部失败，属于预期的缺失行为。
2. 接入认证实现后，测试发现事务内的 MyBatis 查询缓存可能返回授权撤销前的数据。将查询缓存范围设为 `STATEMENT`，授权读取不复用旧结果，回归通过。
3. 补充并发改密与失败登录审计持久化测试，确认只有一次并发改密成功、旧会话失效、失败登录审计真实提交。
4. 前端先写会话/路由测试，补写竞态测试后确认“清除会话后旧恢复响应重新写入身份”失败，再通过请求代次和令牌比对修正。
5. 新增 HTTP 拦截器回归，验证旧会话迟到的 401 不清除新登录的身份。
6. 浏览器测试首轮 12/14 通过，另两项因点击 Element Plus 隐藏的原生 input 超时。改为点击用户可见的“大字”标签，并同时验证 switch 状态和大字样式，随后 14/14 通过。
7. 最后自查补充多角色进入账号页后的身份保持，以及不支持 HTTP 方法应返回 405 的测试，先确认失败，再修正角色状态与统一异常映射。

## 审核重点

| 检查项 | 结论与证据 |
|---|---|
| 认证边界 | 仅 POST 登录免认证；无有效令牌的读取和修改均为 JSON 401 |
| 会话与密码 | 32 字节安全随机令牌；只存 SHA-256 摘要；8 小时过期；BCrypt；密码限制包含 UTF-8 字节上限 |
| 退出与改密 | 退出撤销当前会话；改密撤销全部会话；登录和改密锁定同一用户行，避免并发旧凭据继续创建会话 |
| 权限 | 每次请求读取当前角色及账号状态；网点 Service 执行资源鉴权；家属不能通过意外的员工网点绑定获得员工权限 |
| 个人信息 | 专用 DTO，手机号脱敏；不返回实体密码字段；拒绝请求夹带 id、roles 等未声明字段 |
| 前端恢复 | 不从浏览器缓存信任角色；失效会话清除；网络故障保留令牌并提供重试；旧异步响应不能恢复清除的身份 |
| 数据库隔离 | 每次后端测试创建独立临时库，使用真实 MySQL 和迁移；完成后清理，不清空业务库 |
| 演示初始化 | 仅 dev 可启用；显式开关、环境密码、拒绝覆盖已有用户 |
| 界面 | 查看桌面和手机截图；移动账号页无横向溢出；登录有等待与失败反馈 |
| 范围 | 菜单仅显示本批已实现页面；未把未来业务页面作为已完成功能 |

过滤器通过 Spring Security 的 SecurityFilterChain 注册，避免作为 Servlet Filter 再次注册，参考 [Spring Security 官方架构说明](https://docs.spring.io/spring-security/reference/servlet/architecture.html)。本项目仅用 Authorization header 认证，不接受认证 Cookie 或 HTTP Session，因此未启用 Cookie 场景的 CSRF 机制。

## 文档落地决策

- 原 T01 要求退出，但接口清单没有列出退出路径，补充 `POST /auth/logout`。
- 原文档未指定令牌类型，选择可立即撤销的数据库不透明令牌，符合单体/MySQL 边界，不增加 Redis。
- `.env` 由脚本加载，Spring Boot 不自动读取；只在本机保存开发凭据。应用、文档和示例不内置真实密码。
- 原始 SQL 是起始 schema；用 Flyway 纳管版本，禁用自动 baseline 和 clean，不自动接管已有业务表。
- 测试新增 Vitest 3.2.7、Vue Test Utils 2.4.6、jsdom 26.1.0、Playwright 1.56.1，均精确锁定。首次选用 Vitest 4.1.0 时 npm 10.9.4 依赖解析抛出 `edgesOut` 错误，改用兼容现有 Vite 的 3.2.7；业务依赖版本未变。
