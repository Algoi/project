# 项目统一启停管理

日期：2026-10-17。

统一入口为 `./scripts/service.sh`，对整个项目前后端执行 start、stop、restart、status 和 logs，没有单独启动或停止后端的子命令。不带参数显示项目整体状态。后端底层启动脚本由管理器内部调用；日常只需使用统一入口。

启动在后台运行，等待前端网页与后端接口就绪后返回。关闭终端后服务继续运行；重复启动复用已有项目服务。部分组件缺失时补启；启动失败只清理本次创建的进程，保留此前已运行的项目服务。停止也会识别并关闭本项目已运行的 4173 预览。MySQL 仍由系统管理。

`.run/` 保存状态与日志，已加入忽略配置。状态记录进程 PID、启动时间和系统启动标识，核对 `/proc` 的项目目录及服务命令；陌生端口不会被接管或停止。后台启动使用独立进程组，停止时清理启动器和服务子进程；启停命令通过文件锁串行执行。

## 测试

先增加用例验证缺失实现和整体状态不足的失败，再实现管理器。最终 9 项隔离测试全部通过：

- 启动、重复启动、停止及重复停止。
- 识别既有项目服务并整体关闭。
- 外部程序占用端口时拒绝启动且不误杀。
- 启动失败清理本次进程，保留此前已运行的服务。
- PID 记录跨重启失效时不终止无关进程。
- 整体状态区分已停止、部分运行及运行中；仅预览存活仍显示部分运行。
- 整体重启替换全部组件的启动进程。

隔离测试使用临时目录和随机端口，不依赖 MySQL，也不访问项目业务端口。命令：

```bash
python3 -m unittest discover -s scripts -p test_service_manager.py
```

实际项目验证已完成：接管原有前后端和预览，整体停止后三个端口均关闭；随后从停止状态后台启动，并执行整体 restart。重启后两项启动进程 PID 都发生变化，项目整体就绪，MySQL 继续运行。登录网页的桌面、手机 Chrome 测试各 1 项通过。最后保持整个项目运行。
