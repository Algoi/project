# 07 测试方案与验收用例

## 1. 测试策略

至少包括：Service 单元测试（预测、推荐、价格）、Controller/API 集成测试（权限与状态流）、Vue 基本页面交互测试、人工端到端演示。测试库与生产数据隔离。

## 2. 端到端测试

| ID | 步骤 | 预期 |
|---|---|---|
| E01 | 管理员创建两网点，授权食堂、社区操作员 | 两人只能见所属网点；管理员看全局 |
| E02 | 创建菜品并维护价格、营养、过敏原 | 保存正确，负数价格拒绝 |
| E03 | 家属申请绑定老人及补贴、操作员审核 | 未审核不可读健康资料；审核后可用补贴价 |
| E04 | 食堂上报次日菜谱、操作员发布 | 家属仅可订已发布且可售菜品 |
| E05 | 老人设置过敏原/疾病禁忌，进入推荐页 | 命中禁忌的菜品不进入可订项，推荐可说明原因 |
| E06 | 家属代订→模拟支付→食堂出餐→核销 | 金额、订单状态、凭证及核销记录正确 |
| E07 | 社区操作员为老人单日与周期代订 | 逐日生成独立订单；失败日期有结果 |
| E08 | 已付款未出餐取消→社区审核退款 | 退款金额一次、补贴冲减一次；不得重复退款 |
| E09 | 当日菜品临时下架 | 新订单不能选择，已有订单保留待处理 |
| E10 | 配送订单生成配送清单并标注必要禁忌 | 仅配送订单；不泄露完整健康档案 |
| E11 | 老人核销后评价菜品、上传图片 | 未完成不可评价；一项一条评价 |
| E12 | 家属提交意见，操作员回复，升级重大事项 | 本人工单进度正确，其他家属无权访问 |
| E13 | 管理员发给部分网点/角色公告 | 非目标人群不可见 |
| E14 | 家属查看周/月营养报告 | 只统计实际核销餐食，单位正确 |
| E15 | 管理员看板查看订单、营收、补贴、膳食、预测、推荐效果 | 统计能与业务数据核对 |
| E16 | 管理员修改推荐参数、查看操作日志 | 新推荐结果采用新参数，日志记录版本变更 |

## 3. 预测测试（固定样本）

| ID | 场景 | 结果 |
|---|---|---|
| P01 | 同星期历史 4 个营业日人数 10,20,30,40 | 预测 25，样本数4 |
| P02 | 同星期少于3样本，近14营业日人数 8,10,12 | 回退预测 10 |
| P03 | 历史有效营业日少于3 | 预测 null、insufficientData true |
| P04 | 预测目标为明确停餐日 | count=0、closed=true，停餐日不参与其他预测均值 |
| P05 | 历史日期缺失与真实营业但0人 | 缺失不算样本；0人是样本 |
| P06 | 无订单时生成人数预测 | 仍可预测，不能误当已确认菜品份数 |
| P07 | 用户无权限访问其他网点预测 | 403 |

## 4. 推荐测试（固定样本）

| ID | 场景 | 结果 |
|---|---|---|
| R01 | 老人对花生过敏，菜品含花生 | 服务端不可订、推荐排除 |
| R02 | 后台疾病规则显式禁止某食材 | 排除匹配菜品，显示原因 |
| R03 | 新增规则后再次推荐 | 新规则立即生效，日志记录更改 |
| R04 | 4项权重 0.4/0.25/0.2/0.15，各分项 80/100/60/50 | 得分 32+25+12+7.5=76.5 |
| R05 | 权重总和不为1或小于0 | 配置接口拒绝 |
| R06 | 无评分与无偏好 | 按中性分处理，不凭空预测喜好 |
| R07 | 过敏原数据缺失或安全规则无法判定 | 标记资料不足，不默认判安全 |
| R08 | 直接构造禁忌菜品下单请求 | 后端拒绝，而不是依赖前端过滤 |

## 5. 权限与安全测试

| ID | 场景 | 结果 |
|---|---|---|
| S01 | 家属直接请求另一位老人健康报告 | 403 |
| S02 | 食堂人员查询其他网点订单/核销 | 403 |
| S03 | 社区操作员修改管理员菜品价格 | 403 |
| S04 | 构造重复核销请求或并发核销 | 仅一次成功 |
| S05 | 模拟支付重复回调 | 支付流水与订单状态仅更新一次 |
| S06 | 并发相同老人/日期/餐次订餐 | 至多一笔有效订单 |
| S07 | 支付金额/补贴字段被前端篡改 | 服务端重新计算，拒绝不一致 |
| S08 | 上传恶意扩展名、超限文件、目录穿越 | 拒绝 |
| S09 | 审计、列表、报表返回手机号/健康明文 | 不得意外泄露 |
| S10 | 生产配置下请求模拟支付成功接口 | 404或403，不可成功 |

## 6. 33 功能验收逐项签署

通过 `10-需求追踪矩阵.md` 逐一标记代码实现、接口测试和页面验证结果，**不得以某功能“属于未来扩展”跳过原需求**。外部真实支付渠道可以标为“接口完整/模拟联调通过/生产真实渠道待商户接入”，不可标为真实支付完成。
